INTRODUCTION
This is a revised technology stack optimized for free and low-cost hosting, compatible with the updated SRS (v2.0) including the new Module G connectivity features. Every paid service in the original stack has been replaced with a free-tier or open-source alternative that meets or exceeds the stated requirements.
Key principles:
• No mandatory paid services — all core features use free tiers or open-source software
• Single-server deployment on Render.com or Railway.com free tier (sufficient for ≤10 concurrent analyst users and ≤100 citizen users)
• Database and auth integrated into one Supabase account (500 MB PostGIS, 50k MAU free)
• Frontend deployed on Vercel or Netlify (free; same approach as Polluture)
• All external APIs are either free or have generous free tiers (no rate-limiting surprise bills)
• Scalability path: swap individual components for paid equivalents as user load grows

CRITICAL IMPLEMENTATION NOTES
Pre-compute the road network ONCE and store it in PostGIS:
Download the district-level road network from OpenStreetMap using OSMnx. Run pgRouting topology build once. Store as table in Supabase. Query pre-built network for isochrones and connectivity—do NOT run OSMnx on every request.
Pre-generate map tiles once:
After classification, generate .mbtiles using tippecanoe or gdal2tiles. Upload to Supabase Storage or Cloudflare R2. Serve static tiles. Update frequency: weekly or monthly.
Database size planning:
500 MB Supabase free tier supports ~50 km² of classified LULC (at 10 m pixels) + road network + administrative layers. For larger areas, split into zones or upgrade to paid Supabase.
